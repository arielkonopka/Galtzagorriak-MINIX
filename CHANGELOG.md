# Changelog

Galtzagorriak, a MINIX 2.0.0 port for the Flipper Zero. Versioning rules: spec section J
(`docs/spec/galtzagorriak-spec.md`). Newest release first. Feature PRs add one line under
`Unreleased`; the release PR turns it into a version section.

## Unreleased

- (R6.4) Edges on the GPIO header through `poll()`: `/dev/gpio` operation `6` watches a pin, `7` stops; `poll(POLLIN)` waits until a watched pin changes, and a 16-byte read gives the levels plus which pins changed since the last read. The watch belongs to the process that set it and ends with its close or exit. Pins are sampled on the clock tick (1/60 s), and Stop2 waits while something is watched. Kernel +4 B. QEMU tests in the M2 self-test. Base 3.93.
- (R6.8) `/dev/power` shows how the Flipper slept: `up=` seconds since boot, `stop2=` seconds of them in Stop2, and the wake-ups by a button (`wbtn=`) or anything else (`wother=`), at the end of the line. Battery runs no longer need a latency-trace build. The Stop2 time keeps whole minutes apart (45 days instead of 36 h). Kernel RAM unchanged.
- (R2a.5) The shell (`sh`) takes 3.25 KB less RAM per process (login shell, scripts, subshells; 17.9 → 14.6 KB): its 512-byte file read buffers come from its heap only while a script or `.` file is being read, its tables of built-in commands, keywords and signal names are const in flash, its heap grows in 256-byte steps instead of 2 KB, word lists (globs such as `/bin/*`) are no longer copied, here documents are read in 128-byte pieces instead of a 2 KB line on the stack (lines of any length; the end marker must be shorter than 128 characters), and its stack + heap reserve is 10 KB instead of 12 (`echo /bin/*` uses 5.7 KB of it). A command started by vfork gets its environment, and heap room for its redirections, from the shell before the vfork: the child cannot grow the shell's heap (with 256-byte steps it otherwise crashed the shell). Base 3.92.
- (N.6, T17b part 2, #163) The SD card pulled out is shown on the screen: a box "SD card removed / Put it back" ("Different card / Put the original back", "SD card is back / Carrying on") drawn by the kernel over whatever app is in front, with the backlight on as for a key; the app's next frame replaces it. Needed because the launcher's own files are on the card. Kernel RAM unchanged.
- Fix (R2b.11, found in #109): setting the clock no longer gives the run-time cache a fresh daily flash-erase budget: a jump to another date and back (m2test does it) used to start a new "day" and allowed up to 32 more page erases; what today has spent now moves to the new date. A day that really begins still starts afresh. No RAM, Flipper HAL only.
- Tests: `/usr/tests/regtest` (tests package, #160) checks on the device that exec clears the old program's registers (security review U1, #159): it fills r3-r8, r10-r12 and lr with a marker right at the exec trap, and the child `regchild` saves every register from its own entry point, before crtso runs. Flipper: ok as root and as a user; QEMU with the clearing taken out: FAIL r3..r12, so it catches the leak. No kernel or base change.
- (7b.3, part 1) A hardware self test: package `stest` (`/usr/bin/selftest`, **Self test** on the launcher) with a menu, **All tests** in a loop and `selftest -a [-n N] [-k]` for scripts. The tests are modules in `/usr/lib/selftest/` (a program plus a one-line `.d` file; each writes `PASS`, `FAIL reason` or `SKIP reason`), each result is logged in `/home/flipper/apps_data/selftest/log`. Modules so far: **Board** (RTC running, the SD card's size, 1 MB read speed and a write-read-compare of the unused sector before the first partition, battery gauge and charger, the LED chip, USB), **Input** (every button down and up) and **Sound, vibration and light** (scale, vibration, LED colours, display patterns, backlight ramp; the user confirms). The memory and GPIO tests follow. Nothing resident: the app and one module only while they run (selftest 3 KB, a module 2–3 KB). Kernel and base unchanged.
- (7b.3, part 2) Self test: **Memory** (all 256 KB of RAM as an 8 × 8 grid; every free 4 KB block tested in place by MM with March C− through the new `MEMINFO` request `MI_MEMTEST`, root only, and left zeroed, so no process ever sees it; MM RAM +0 B), **Memory: flash** (the 1 MB as a 16 × 16 grid; every installed program's text hashed again with SHA-256 against its install record, a damaged one named) and **GPIO loopback** (jumpers on 2–3, 4–5, 6–7, 15–16: each pin drives the other against a pull-down and a pull-up; the 5 V output read back from the charger). Board: the scratch-sector compare now reads the card itself (`/dev/hd0` closed and opened again), below the lowest partition.
- (N.6, T17b part 1, #163) The SD card pulled out: the card-detect switch is read before every card access; while the card is out every access fails with `ENXIO` (not a garbled transfer), the console says "SD card removed: put it back" with a short buzz, and a card put back is compared with the original by its CID (manufacturer, serial): the same card carries on, a different card is never touched ("Different card: put the original back or power off"). A transfer that fails because the card went is `ENXIO` too. Keeping unwritten changes in memory until the card is back is the FS side (T17a). Kernel +4 B (the CID hash). QEMU test in the M2 self-test (hook `DIOCFAKECARD`, QEMU only). Base 3.91.
- Package `timed` 1.1 (`/lib/pkg/timed_1.1.tar`): the same programs with the #196 alert fix, under a new version so `pkg install` upgrades cards that have 1.0. No other change.
- (R7b.2) Foreground preemption for alerts: `ioctl(FGIOCPREEMPT)` on `/dev/lcd` or `/dev/buttons` (`<minix/fg.h>`) takes the screen and the buttons from whoever has them until `FGIOCRELEASE` or the caller's exit; a second alert meanwhile gets `EBUSY`. The preempted app keeps running (its frames are dropped, its button reads wait); a button read waiting at that moment (the launcher's, an app's) ends with 0 bytes, and one started meanwhile is parked and ends with 0 bytes at the release, so the reader redraws and reads again (MINIX 2 has no free signal for `SIGWINCH`). Found on the device: the launcher's waiting read held the buttons' one reader slot, so an alert's reads failed at once and it rang twice a second. Also: when the foreground app exits without handing the screen back, the kernel clears it at the next tick (before, the next process in its slot seemed to hold the screen, #192). Kernel RAM unchanged (the button queue's counters are 8-bit now). QEMU tests in the M2 self-test. Base 3.90.
- Tests: `/usr/tests/swaptime` (tests package) measures how long a swapped program takes to wake: a 64 KB helper (`swaptime64`, text in flash with `pkg flash` so MM may swap it) is swapped out by `MI_SWAPTEST`, woken by a signal, and checks its 60 KB came back whole; rounds without the swap-out give the signal's own round trip. On the Flipper (the owner's card): swap-in of a 64 KB image 69 ms (30 rounds). No kernel or base change.
- Fix: alarms and reminders from `timed` showed on the screen but did not ring, vibrate or blink: `libapp` passed the notification flags to `/usr/lib/alert` as one character including the internal "show" bit (`?` instead of `7`), which alert read as 0. Seen on the device (#109, AC7b.R1). Also: the alert keeps the backlight on while it rings, so the first OK or Back press is not swallowed by the backlight's idle timeout. Package `timed` (libapp); base unchanged.
- (R4b.6, #131) `poll()` waits for the console and the keys: the TTY task and the Flipper device task answer `DEV_SELECT`, so a terminal is readable when a read would not wait (a whole line, a character in raw mode) and writable when no write is in progress, `/dev/buttons` is readable when a key event is queued for the caller (not while another app owns the buttons) and `/dev/speaker` writable when no tune plays; each wakes its pollers once with `DEV_SELECTED` (the buttons on a new event). Before, these counted as always ready, so a program waiting for keys and a pipe at once, or libfuri's idle `poll()`, woke every tick. IR, RFID and Sub-GHz raw stay "always ready" (they capture only while a read waits). Kernel RAM unchanged (the state sits in `tty_t`'s padding and two bytes freed from the button ring's counters). QEMU tests in the M2 self-test. Base 3.88.
- (R6.5, parts 4–5) Emulating a 125 kHz tag, and an **RFID** app on the launcher. `rfid emulate EM B0 B1 B2 B3 B4` makes the Flipper pretend to be that EM4100 tag for a reader: the reader's own field is the clock — the kernel counts its carrier (TIM2 external-clock mode on the antenna's carrier node) and loads the antenna in step with it by two DMA channels walking the waveform (`ioctl` `RFIDIOCEMU` on `/dev/rfid`), so it cannot drift and the CPU is idle while it runs; a close or Ctrl-C stops it (EM4100 only for now; verified on a real door reader). The **RFID** launcher app ties it together: **Read** a tag and save it to the SD card (`/home/lfrfid`, the stock `.rfid` format, named by its number), **Saved** lists them to **Emulate**, **Write to tag**, **Rename** (an on-screen keyboard: Shift cycles lower/UPPER/symbols, Bksp/Del/Ret) or **Delete**, and **Add manually** types a number in — reading and writing through the `rfid` command, emulation through `RFIDIOCEMU`. Verified on the device (Read/Saved/Emulate/Write/Rename). Kernel RAM unchanged. Base 3.89. Cards that had the part-4 **RFID emu** entry lose it (it is part of the RFID app now).
- (R7b.3, R7b.4) Timers and alerts, nothing resident between events: package `timed` (`/lib/pkg/timed_1.0.tar`) with `/usr/lib/timed`, which INIT runs on `SIGRTC` (alarm, time set, boot): it reads the spool `/var/timers` (one 0600 file per timer, root:timers 1770 on the SD card; `once`, `daily` with weekdays, `interval` in a window aligned to its start; local time with `/etc/TZ`; `Missed: skip|fire-once` after power-off or a clock jump), fires what is due (`notify` or `run` as the file's owner with `--timer ID`), arms RTC Alarm A for the earliest next time and exits (≈ 2 KB used, `-n` time override for tests); `/usr/lib/alert` shows title, text and time on `/dev/lcd` when no app holds the screen, rings, vibrates and blinks, OK/Back/Up-Down = done/dismiss/snooze. Notification policy `/etc/notify.conf` and `~/.config/notify` (volume, vibro, LED, do-not-disturb): alarms always ring, reminders and info wait. `libapp` (`flipper/lib/app`): `timer_add/remove/list`, `notify_post`, `settings_get/set` (`/home/flipper/apps_data/<app>/settings`), `on_redraw`. Manifest fields `Timers:`, `Notify:`, `DeskMode:` (`mkpkg.py`, checked by `pkg`). Kernel and INIT unchanged (0 B). Base 3.82. Host tests `make -C flipper/lib/app test` (in `tests/host`), QEMU test `tools/timedtest.py`.
- (R5.2) `libfuri` GUI for ported stock apps (`flipper/lib/furi`): the stock `gui` API inside the app's own process: ViewPort and Canvas (u8g2 into a 1 KB page buffer written to `/dev/lcd` in one write, only when something changed), the four stock fonts and the stock icons as `const` data, input from `/dev/buttons` as stock (Press, Short or Long/Repeat, Release; 300 ms long, 150 ms repeat) on one "gui" thread that blocks only itself, ViewDispatcher (one queue, no FuriEventLoop), SceneManager and the modules Submenu, Popup, DialogEx, TextInput, ByteInput, VariableItemList, Widget, Loading; Window-layer apps get the black title bar. `malloc()` in libfuri code returns zeroed memory as stock. Host tests with 16 reference images (`make -C flipper/lib/furi test`), QEMU smoke test `furihello` in the M2 self-test, `/usr/tests/furihello` on the Flipper. ~20 KB code per app for a Submenu app (until the shared library), 2 KB gui stack + ~0.6 KB state + 1 KB frame per app; kernel 0 B. FileBrowser waits for storage (R5.3).
- (Phase 12, R12.28) Swap to the SD card, plain mode, off by default: with `swap=plain` in `/etc/rc.conf` programs that wait in `wait`/`pause`/`sigsuspend` give their RAM back to the swap partition `/dev/hd3` (type 82 only, never internal flash), when a program cannot start (waited ≥ 1 s) or at idle to keep a reserve free (`swapon -r`, 16 KB, waited ≥ 10 s, ≤ 256 KB a minute), and come back to the same addresses before they wake (the gap zeroed). Each image has a CRC-32: a damaged one is killed, never run. Set-uid/set-gid programs, `login` and `Secret: yes` packages (`elf2mnx --secret`) are never swapped. The launcher's app goes low in RAM and is never swapped, everything else goes high. A card that fails ends the swapped programs ("lost"). `swapon` command, `free -v` shows the swap state; `swap=crypt` is refused until encryption (12b). Kernel: a `P_SWAPPED` flag and `SYS_SWAP` (RAM +0 B); MM +56 B. Base 3.81. QEMU test `tools/swaptest.py` (`tests/swapper`).
- (R5.1 follow-up, #181) `libfuri` idles in `poll()` instead of `alarm()`: `furi_delay_ms()` and furi timers wake within a tick (1/60 s) instead of up to a second (`furi_delay_ms(100)` measures 100 ms in QEMU), and a thread waiting for a pipe, terminal or `/dev/buttons` through the internal `ffd_read()`/`ffd_wait()` no longer stops the other threads. Devices that do not answer `DEV_SELECT` yet are read with `O_NONBLOCK` and retried per tick, never in a spin. +0.7 KB code and 10 B .bss per app, 24 B per waiting fd (on the thread's stack). No change on the Flipper image.
- (R4b.6) `poll()` for programs (`<poll.h>`, `man 2 poll`): wait for pipes, FIFOs and character devices at once, with a timeout in ms (rounded up to the 1/60 s tick) and `EINTR` on a signal. Pipes and FIFOs are judged by FS; a device is asked by its driver (`DEV_SELECT`, `DEV_SELECTED` in `<minix/com.h>`, protocol #131) and counts as always ready until its driver answers (terminals and `/dev/buttons` next). FS +268 B RAM (one 16 B poll record per process). QEMU tests in the M2 self-test. ABI 2 unchanged: two libc entries appended. Base 3.80.
- (Phase 3, R3.2–R3.7) Accounts and packages: a new card has no open root any more: the console asks for the root password before its first login prompt (`getty` runs `passwd root` while root has none, `login` refuses everybody until then; `/etc/rc` never waits, so the launcher starts without a USB host), root is `##root` with its hash in `/etc/shadow` (mode 600), `passwd` takes its salts only from `/dev/random`, a failed password check takes 2 s and `pwdauth` answers shadow checks only for root or the user itself (`su` asks as root). `pkg` receives into and unpacks under root-only `/usr/var/pkg/in` and `/usr/var/pkg/tmp` (scratch names from `/dev/random`), installs only what it received in that run, checks the archive before unpacking (no absolute paths, `..`, over-long names, links or devices), checks `Package:`/`Depends:` names, builds paths with the new libc `snprintf`/`vsnprintf`, and `pkg remove` deletes only whole recorded paths. The sticky bit works: in `/tmp` and `/usr/tmp` only a file's owner or root may delete or rename it (`chmod` used to drop the bit). `getpass()` falls back to standard input without a controlling terminal. Existing cards: the base package moves root's hash to `/etc/shadow` and makes `/tmp` sticky. QEMU check `tools/p3check.py` (QEMU builds hash with 1000 rounds instead of 5000, and their `/dev/random` stays a weak, marked fallback); tests `pkgbad`, `pkgplant`, `sticky`, `pwdcheck`. Kernel RAM unchanged. Base 3.79.
- (R5.1) `libfuri` core for ported stock apps (`flipper/lib/furi`): cooperative threads inside one process with stacks from the program's stack gap (user-space Cortex-M4 switch, stack canaries), message queues, event and thread flags, mutexes, semaphores, timers, records, `FuriString`, `FURI_LOG_*` to `/dev/log`, and `furi_check`/`furi_crash` ending only the app (`abort()`); stock API names and return codes. Host tests (`make -C flipper/lib/furi test`, run with `tests/host`) and `/bin/furitest` in the QEMU self-test. ~12 KB code per app until it joins the shared library; 84 B per thread + stack, 32 B per queue + messages. Idle sleeps are whole seconds until `poll()` (R4b.6). No change on the Flipper image.
- (R6.5, part 3) Reading T5577 blocks and clearing a password: `rfid clear` takes the password off a locked 125 kHz tag (as a hardware cloner often sets) and makes it programmable again, writing block 0 with the password bit clear and reading it back; it tries no password, then `-with HEX`, then the proxmark3 list of common cloner passwords, and stops at the first that opens the tag. `rfid dump [BLOCK]` reads one block (0 the configuration, 7 the password) and prints its 32-bit word. A block read holds the field up across the read command and the reply (`/dev/rfid` `ioctl` `RFIDIOCFIELD`); the command goes out on the IR transmitter's engine, the reply is captured as a read after a settle, and the block's repeating word is decoded like the EM4100 Manchester. Kernel RAM unchanged. Base 3.78.
- (R6.5, part 2) Writing blank 125 kHz tags: `rfid write EM B0 B1 B2 B3 B4` makes a T5577 (or EM4305, as the stock firmware tries next) fob or card an EM4100 with that number and reads it back. The field gaps are timed by the IR transmitter's engine on the RFID antenna (`/dev/rfid` write). Base 3.77.
- (R6.5, part 1) LF RFID reading: `rfid` reads a 125 kHz tag held to the back and prints its EM4100 number as the stock app does (`EM4100 04 00 98 3D C5`); `/dev/rfid` gives the tag's signal timed by the pulse engine (the field from TIM1, the antenna's comparator into TIM2, DMA into the reader). Other kinds (HID, Indala) are shown as a summary for now. Base 3.76.
- (R4b.7, part 2) `/dev/subghzraw`: what the Sub-GHz receiver demodulates (OOK), timed by the pulse engine like `/dev/ir` (durations in µs, carrier first); tune with `/dev/subghz` first. `ir rx -r -d /dev/subghzraw` shows it. Without an RSSI threshold the receiver's noise toggles it too (as stock "Read RAW" without one). Base 3.75.
- (R4b.7, part 1) The pulse engine: infrared frames are received by timer capture and DMA straight into the reading program's buffer (1 µs resolution, one interrupt at the start and one at the end of a frame instead of one per edge; the 64-byte receive ring is gone). `/dev/ir` reads as before. A frame may be sent while another program waits for one. Kernel −16 B.
- (R6.2, R7b.1, R7b.3, T14c) The clock: setting the time (`date`) writes the RTC, so it survives resets and power-off, and the time is read from it (it keeps counting in Stop2). `/dev/rtc` and the `rtc` command (root, new group `timers`): RTC Alarm A up to 27 days ahead, smooth calibration (`rtc cal`, 0.954 ppm steps). An alarm wakes the CPU from Stop2 and sends the new signal `SIGRTC` (7, ignored unless caught) to INIT, which runs `/usr/lib/timed` when installed (also at boot and after the time is set). Switched off on battery, the Flipper is started again by the alarm, early by the boot lead (`rtc lead`, first 10 s); `rtc` tells whether this boot came from the alarm. Base 3.74.
- (R2b.9, ABI 2) One shared C library in flash: `minix.bin` carries libc once (18 KB at 192 KB into flash, after the system image), and every program calls it in place instead of carrying its own copy. The 96 base programs' text shrinks from 593 KB to 257 KB (the base package from 770 KB to 470 KB; the programs flashed by `make base-flash` from 136 KB to 92 KB), so more programs fit the installed region and the text cache, and a program run from RAM needs less of it; each process keeps about 0.6 KB of libc data (errno, stdio, malloc state), on average 0.26 KB more than before. The installed programs now start at 256 KB. Programs and packages fit only the libc of their own build: exec refuses others (ENOEXEC), `pkg` refuses a package with another `Libc:` id, and `free -v` shows the library. Flash `minix-base.bin` and rewrite the card from the same build. Base 3.73.
- Console: program output and echo on the USB serial port, the header UART and the LCD console end lines in CR LF again (`OPOST`/`ONLCR`, the termios default): `minicom` and `picocom` with default settings no longer show a staircase. Raw output (`stty -opost`, `mined`, `rz`/`sz`) stays untouched. QEMU check in the M2 self-test. Kernel RAM unchanged.
- Security (U1): `exec` clears every register of the old program before the new one starts (r0-r8 and r10-r12 used to carry over, e.g. from a setuid program).
- (R7b.5) LED patterns: `echo blink red >/dev/led` (also `fast`, `double`, `pulse`; `rainbow`, and `dual`, `dualsoft`, `morph` with two colours; colours red, green, blue, yellow, cyan, magenta, white or `#rrggbb`; `off`) runs the pattern in the LED driver chip itself, with the CPU free to sleep. Setting the screen backlight no longer resets the LED chip's engines and channel map.
- (R2a.5) Smaller programs in RAM: `sed`, `fgrep`, `cmp`, `cat`, `ls`, `tar`, `ed`, `mkfs`, `rev` and the launcher keep at most 4 KB of static buffers (were up to 10 KB): reads in 512 B–1 KB pieces, `cat` with one buffer, `sed` sizes its command table and string pool by the script. `make ramcheck` fails when a base program goes above 4 KB `.bss` again (`tools/bsscheck.py`, exceptions with their reason in `flipper/bss-exceptions.txt`: `lat`, `ir`). `fgrep` no longer overruns its buffer on input that comes in odd pieces; lines up to 2047 characters stay whole. `sed` compiles each regular expression on the stack and keeps only its real size (chmem 10 KB: scripts of up to 100 commands and about 2.5 KB of compiled text). `rev` no longer crashes on a line longer than 4 KB (it reverses it in 4 KB pieces). Base 3.72.
- (R6.4 part 2, R4b.5) `/dev/adcs`: sample one header pin at a fixed rate (100 Hz–100 kHz) straight into the reading program's buffer (timer-triggered ADC, DMA, the process pinned meanwhile); `/dev/adc` averages its reference reading again (it wandered ±1.5 %). Base 3.71.
- (R8.1, part 1) Sub-GHz listening: `echo 433920000 > /dev/subghz` tunes the CC1101 (stock bands, stock OOK 650 kHz receive settings, the RF path switch as stock) and `cat /dev/subghz` shows the signal strength in dBm; receive only, no transmit path exists yet. Base 3.70.
- (T16, R6.10) Backlight gestures: hold Left+Up 1.5 s to keep the backlight off (keys still work in the dark), Right+Down 1.5 s to keep it on; the same again returns to normal. The status LED blinks red faster and faster while you hold, a short buzz confirms. Also `backlight force off|on|auto`; a reboot gives the normal light back. Apps that need those keys together can turn gestures off (`BTNIOCGEST`). Base 3.69.
- (Phase 2d, ABI 2) Time past 2038: `time_t` is 64-bit for programs (files store times as unsigned 32 bits, 1970 to 2106-02-07; file systems made before mount unchanged); the clock keeps UTC and local time follows `TZ` (`date -u`, `date ... Z` sets UTC, `MMDDCCYY` dates); the uptime counter no longer misbehaves after 414/828 days; `putenv()` now works with `getenv()`; `find`, `login`, `tar` and `mkfs` fixed for 64-bit times, and `make check`/`ramcheck` run a Year-2038 audit. Programs and packages of ABI 1 no longer run: rewrite the card and flash `minix-base.bin` of the same build. FS −72 B RAM. Base 3.68.
- Security review, weekly run 1 (`docs/security/2026-11-16-fs.md`): a damaged file system on the SD card no longer stops the whole system: a bad zone number in an indirect block reads as a hole, freeing an already free zone or inode only prints "run fsck", and a super block whose bit maps do not cover its inodes and zones is refused at mount instead of corrupting the inode table. QEMU test `tools/fsdamage.py`.
- (R4b.9) SD transfers check their CRC16 with the STM32WB's CRC unit instead of in software (a 512-byte sector: ~150 instead of ~10 000 cycles), after a self-test at start; on a mismatch the software CRC stays.
- The LCD is written at 8 MHz instead of 4 (a frame in about 1 ms instead of 2: the CPU is free sooner for everything else).
- Fixes from the device check: `/dev/adc` read nonsense (VREF+ floats on the Flipper): it now turns the internal 2.5 V reference buffer on for the reading, as the stock firmware does; the range is 0–2.5 V, `>` above it, and the line ends with `ref=` (the measured reference). Fault reports showed `addr=e000ed34` for every memory fault on the device: the address is now read before the fault status is cleared. The About screen's uptime counts. Base 3.67.
- Security review of the kernel (`docs/security/`, weekly from now on): a USB host or the header UART flooding the console can no longer freeze the Flipper or make the watchdog reset it (the TTY task works on input in 2 ms slices, and echo to a USB host that does not read is dropped instead of waited for); a damaged SD card can no longer hang the boot with a looping extended partition table or hold the CPU for seconds when it stops answering. PC tests for hostile input: `make -C flipper/tests/host` (partition tables, the USB stack) and `tools/conflood.py` (QEMU).
- (R6.1) Charging settings written to `/dev/power` (root): `profile full|care` (charge to 4.208 V or about 4.0 V), `gentle on|off` (1 A instead of the stock 2 A), `otg on|off` (5 V on the GPIO header); the profile and gentle charging are kept in an RTC backup register. `/dev/power` also shows `vreg=`, `ichg=` and `otg=`. Base 3.66 (`/dev/power` 0644). Once a minute the kernel checks the battery: on a charger, charging pauses outside 0–45 °C (gauge temperature; resumes between 2 and 43 °C); below 3.3 V no new flash erases start.
- Fix (#108): a program started right after an update, with memory short, could get garbage argument pointers and crash once (seen as `signal 11 ... addr=e000ed34` in `ed` and `wc`): exec copied the text to the flash cache through the buffer that held the new stack image.
- About screen: one fact per line (name and version, MINIX base, machine and ABI, host, uptime); the version line no longer runs off the screen. Base 3.65.
- (R6.4, part 1) `cat /dev/adc` shows the voltage in mV on the GPIO header pins with an ADC input (2, 3, 4, 7, 15, 16) that are left analog (`gpio N off`, the default), and the supply (VDDA): 16x hardware oversampling, calibrated by the chip's internal reference. Base 3.64.
- (R6.3) Timed vibration: writing a number of milliseconds (2–999) to `/dev/vibro` buzzes that long, ended by the kernel's ms timer (also from Stop2), so the program need not wait; `0` and `1` still turn it off and on.
- (R6.7, part 1) iButton: reading `/dev/ibutton` with a key on the contacts gives its 8-byte ROM (family, serial, CRC checked); no key: ENODEV. 1-Wire timing in the kernel with interrupts masked at most 70 µs per bit. Base 3.63.
- (R4a.5, part) Flash ECC: an uncorrectable error stops the system with "flash ECC: uncorrectable error at ADDRESS" instead of an unexplained exception; a corrected single-bit error is reported in one line (a page wearing out).
- (R4a.6) Stack overflow detection: a DWT watchpoint guards the kernel stack and the running task's stack; writing past either stops the system with "stack overflow in TASK" instead of corrupting memory silently.
- (R4b.8) The app started from the launcher owns the screen and the buttons (`FGIOCSET` ioctl, `<minix/fg.h>`): frames from other programs are dropped, their button reads wait. Holding Back for a second ends the app (SIGTERM, then SIGKILL after 3 s), as on the stock firmware. Base 3.61.
- (Phase 4a: R4a.1, R4a.2, R4a.3, R4a.7) Kernel hardening: interrupts are masked with BASEPRI, so a fault inside a kernel critical section is reported as what it is; a program whose code is in flash cannot execute from its RAM (stack, heap), and a 32-byte guard at the end of its heap stops a runaway stack with SIGSEGV before it overwrites the heap; flash writes keep the MPU on (only the target page opens, for the kernel); the USB console checks the length of SET_LINE_CODING. `m2test` checks NULL, the stack/heap guard and (with the text in flash) execute-from-stack.
- (T14c, part 2a) `halt` powers the Flipper off for real (the charger's ship mode, as the stock firmware): screen and backlight go dark, the battery is disconnected; hold Back (or plug in USB) to start it again. With USB connected it waits for the cable to go.
- (T14c, part 1) The charger's state: `/dev/power` gains `chg=` (0 not charging, 1 pre-charge, 2 fast, 3 done) and `vbus=` (the charger's VBUS_STAT), and the Power app says "charged" or "charging". The charger's ADC converts on demand instead of every second; with power on the USB connector the Flipper stays out of Stop2 so USB can start. Base 3.60.
- (T14d, part 1) On battery, 2 minutes after the backlight has gone off the screen goes into power save as well (blank); any key brings the same picture back at once. With USB connected the screen stays on.
- (R4b.2) The millisecond timer works in QEMU too (CMSDK APB timers), so its users (`poll()` timeouts, R4b.6) can be tested in CI; the idle loop asks `hal_can_stop2()` before trying Stop2.
- (T15a) Battery on the screen: `/dev/power` (the BQ27220 fuel gauge, read only: charge, voltage, current, average and standby current, temperature, USB) and a **Power** app in the launcher with the current now and the idle current (`docs/manual/power.md`). Base 3.59 (its postinst adds `/dev/power` and the launcher entry on older cards).
- (T14b) Deep sleep when idle: with nothing to do and no USB cable, the Flipper stops its clocks (Stop2) and wakes on a button or its timer (at most about 1 s later); buttons now interrupt instead of being sampled on the clock tick, debounced by a new millisecond timer (LPTIM1). `lat` shows the time in Stop2 and why it was not taken. The UART console on the header loses input while asleep: keep USB attached to use it.
- (T14a) Less current at idle: the core runs from the SMPS step-down converter, and the Sub-GHz and NFC chips sleep from boot (they idled with their crystals running).
- QEMU board: SysTick starts at the lowest priority, so a tick during early boot can no longer enter the kernel before the first process (it locked up about 1 boot in 30 on a busy host: the random `powercut` failures in CI). The Flipper already did this.
- (Phase 2c) `vfork`: the shell, init, the launcher and pkg start programs without copying themselves first, so commands still start when memory is short (`vfork(2)`). Base 3.58.
- The LCD backlight dims 10 % a second from 5 s before its timeout (default 15 s, spec #89) and then fades out (0.5 s); the next key or button brings it back at once (when it is off, that press only turns it on). Reading `/dev/backlight` ends after its 4-byte state.

## 0.1.0 (2026-11-14): Phase 1 complete

First numbered release. Covers everything up to Phase 1. ABI 1.

System
- MINIX 2.0.0 kernel, MM and FS on the STM32WB55 (Cortex-M4); root file system on the SD card.
- Real `init`, getty, login, `/bin/sh` and about 80 commands; launcher with apps; Console app on the LCD.
- Position-independent user programs (separate I&D) and the flash text cache: program text runs from internal flash.
- Memory protection with the MPU; each process is confined to its own memory.
- Packages with `pkg`; the base package can be updated over the USB cable.
- Fork switches 26× faster; exec without heap; faster SD with CRC checks and multi-block writes.

Hardware
- `/dev/random` (hardware RNG), `/dev/zero`, `/dev/gpio` (header pins), `/dev/vibro`, `/dev/speaker`; `gpio` and `beep`.
- Watchdog, `reboot -d` (to DFU), console bell.

Security (Phase 1)
- Closed the local-root holes: sigreturn checks, unprivileged frame access, relocation bounds,
  flash-cache entries keyed by file owner, aligned message pointers, no whole-RAM MPU fallback (R1.1–R1.7).
- `umap()` checks the whole buffer against the process's memory (S13).
- No getty root-shell fallback; `passwd` overflow fixed; SHA-256-crypt passwords.

Measurement
- `make ramcheck` with `flipper/ram-budget.txt`; `latcheck` kernel and `lat` with the L1–L10 baseline in `flipper/PORTING.md`.
- Static RAM: kernel 17556 B, MM 10684 B, FS 27856 B, INIT 1748 B.

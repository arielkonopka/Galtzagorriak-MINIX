# Changelog

Galtzagorriak, a MINIX 2.0.0 port for the Flipper Zero. Versioning rules: spec section J
(`docs/spec/galtzagorriak-spec.md`). Newest release first. Feature PRs add one line under
`Unreleased`; the release PR turns it into a version section.

## Unreleased

- (#284, R6.8) **`wother` in `/dev/power` no longer wraps after about 18 h**: the Stop2 timer wake-up count is 32 bits now (136 years at one a second), so the two readings of a night give the right difference. It uses the 2 bytes of padding the old statistics record had: `pm_stat` stays 12 B, kernel RAM +0 B (ramcheck 14884). `wbtn` stays 16-bit (65536 button presses). - `tools/twoflip.py`: **RFID vectors every protocol takes.** Keri (bit 31 set), Idteck (the `IDTK` prefix), and HIDProx, AWID, HIDExt and Indala26 (their frames do not carry the last bits, which a reader leaves 0) get their canonical forms. They were computed on the host by encoding with one protocol dictionary and decoding with a fresh one; decoding with the encoder's own dictionary hides the bits a frame does not carry. Nexwatch, GProxII, Noralsy and Indala224 refuse the test pattern (their checks fail), so they use `lfrfidtest`'s fixed vectors. `rfid emulate` gets 8 s to start, not 3 (Nexwatch needs 3.9 s on the device). On the device GProxII and Noralsy now PASS both ways (were MISSING/FAIL), and AWID, HIDProx and HIDExt M→U PASS (they were FAIL on "wrong last bits": MINIX's emulation was right). Keri M→U reads in about 1 of 3 tries.

- (#331) **Busy processes no longer freeze the launcher; `fork()` of a large process returns.** A shadow group (forked processes without an MMU) was swapped every clock tick (60 flips/s), and each swap put the next member at the head of the user queue, ahead of the launcher or of a parent back from `fork()`. Now the clock swaps a group member in only at the end of a quantum (10 flips/s for fptest's pair), at the tail of the user queue. A woken member is swapped in before preempted ones. Live FP registers are saved before a flip. M2 check: four `O_NONBLOCK` writers spinning on EAGAIN (`/bin/spinfifo`, QEMU only), started by a plain `fork()` of m2test. The fork returns, key → frame is 33 ms (before: the fork never returned), and ACK.3 is 100/100 ms (before: 250/166). fptest's time-sliced check now runs for 2 s of wall time. Two older bugs this exposed are fixed: a process whose FP frame the CPU had padded got S16-S31 back 4 bytes off after another process ran (S16 held S17's value), and `malloc` failed when its 1 KB-rounded break fell into MM's safety margin below the stack, even though the request fitted (the launcher then listed only 2-3 of 12 apps). Kernel/MM RAM +0 B, no flash writes.
- (#302, R8.1, on the device) **`subghz rx` decodes on the Flipper**: a `/dev/subghzraw` (and `/dev/ir`) read ended only after a silence. The CC1101's OOK output is noise when nothing is sent, so the reader's buffer filled with noise and the read then waited for 100 ms of quiet that never came while a remote sent: the whole transmission was lost (twoflip: 0 packets decoded). The kernel now also ends a frame when its buffer is full (the ms timer looks every 10 ms while a frame is being captured; no timer when nothing comes), and `subghz rx` adds its 20 ms end-of-frame silence only after a frame that ended in one. Kernel text +32 B, RAM +0 B, no flash writes.

- (T18a, spec 12g, R12.29–R12.33, #305) **Less SD card wear from swap**: the slot header holds a CRC-32 of every 4 KB chunk. A swap-out writes only the chunks that changed since the header on the card, and nothing at all if none did (a parked app woken by a timer that changed nothing costs the card 0 bytes). The CRCs leave out the gap `[brk, sp)`, which swap-in zeroes, so a signal handler's frame below `sp` no longer forces a write. Swap-in checks every chunk, skipped ones too. On demand: CRCs first, then the header, then the changed chunks in ascending order. The reserve's job writes the header last, and voided jobs are safe (`SWAPHDR`). A process woken from the card (`SWAPHOT`) is left alone by the reserve until it has waited 120 s once; on-demand swap ignores the flag. `mkpart` and the image tool start partitions on 4 MiB boundaries (new cards). New **`erase /dev/hdN`** (root; refuses `hd0`, mounted partitions and active swap) with the `DIOCERASE` ioctl; `/etc/setup` stage 2 runs it over `/usr`, swap and `/home` before `mkfs` ("Preparing the card..."). On the Flipper it answers ENOTTY until T18b and setup goes on; in QEMU the range becomes 0x00, and only 64 KB pieces that hold data are written. New test `tests/swapwear` (AC12.14, AC12.15) in `tools/swaptest.py`. MM RAM −4 B, kernel +0 B, no flash writes. Manual: [Swap](docs/manual/swap.md), [Installation](docs/manual/install.md); `erase(8)`. Base 4.40.

- **Ctrl-C at the shell prompt no longer logs you out** (about 1 in 100 times). `sh` runs simple commands with `vfork()`, and the child sets `talking = 0` in the shell's own memory before `exec`; a Ctrl-C that reached the shell during that window ran its handler as soon as `vfork()` returned, before `talking` was put back, so the handler took the login shell for a script and ended it. Now SIGINT and SIGQUIT are blocked across `vfork()`: the shell unblocks them once its state is restored, the child once it has set them to their defaults (ignored ones stay ignored), so the Ctrl-C still stops the command and never the shell.

## M1: blocks past 4 GiB wrap onto the swap slots

`blk_on` takes the swap partition's size from the card's partition table
and cuts all of it into 256 extents. `bk_io` then computes a byte offset
in 32 bits (`sw_dio`, "swap stays below 4 GiB", R12.39). `mkpart` never
makes a swap partition that large, but nothing checked a card made
elsewhere. On an 8 GiB swap partition the second half of the block space
came out on top of the first 4 GiB: the 16 swap slots (other processes'
images, root's among them) and the blocks of whoever holds the first
half. A process that is not root gets the upper half by reserving after
another holder, so with such a card an app could rewrite a swapped-out
process. Blocks are off by default (`blk=on`).

Fix: `blk_on` uses only what lies below 4 GiB - 512 B (`BK_MAXSECT`), on
primary partitions and on `hd3a` alike (the subpartitions use `hd3a`'s
size). MM RAM +0 B. Test: `tools/blktest.py -4` grows the swap partition
by 4.5 GiB (QEMU's card hole) and `blktest -4` checks that the block space
ends below 4 GiB; it fails on the old MM.

## K9: SD start holds the CPU

#379 retries CMD0 up to 40 times, 10 ms apart, with a power cycle (250 ms
off, 100 ms on) in the middle, all busy waits in the disk task. With an
empty slot or a card that says nothing this ran at every open of a disk
device: about 0.8 s in which no other kernel task ran (screen, buttons'
task work, infrared). Below the watchdog's 2 s, so no reset, but the
class of K3. The 10 ms waits now call `hal_disk_yield()` as the ACMD41
loop does. The power cycle is left as it is: while the card's lines are
driven low the LCD shares the bus, so yielding there needs a look on the
device (issue for the device lane).

## M2: executable header sums

`a_data + a_bss` and the click rounding of `a_text` and `a_total` were
added in 32 bits without a check. A file with `a_data = 0xFFFFF000` got a
small image and a 4 GB load into it. FS loads through the kernel's
`umap`, which ends the read at the image's end, and the relocation
checks (S2) refuse the rest, so nothing outside the process was written.
`read_header` now refuses such files (`ENOEXEC`) before anything is
allocated.

# Security review 2026-11-19: kernel hot spots, old and new code

Scope: the kernel image on `main` at `7fd5a3f`, old MINIX code and the
Flipper drivers alike, at the user's request (2026-11-19). Threat model and
method: [README.md](README.md). The rule the fixes follow, in the user's
words: **root may do everything, other users may not.** Apps started by the
launcher are not root.

## Summary

| # | Severity | Problem | Status |
|---|---|---|---|
| H1 | High | `DIOCSETP` on `/dev/rom` (mode 0644) moved the driver's window: any process could read all RAM, or reset the device with a bus fault | **fixed**: root only (FS `do_ioctl`), M2 test |
| H2 | High | `exec` did not stop a process's RFID stream, RFID or iButton emulation, pulse list, ADC stream: DMA and interrupts went on using memory given away | **fixed**: `do_fresh` calls `flipdev_xit`, M2 test |
| H3 | Medium | A held RFID read cancelled before its capture was armed computed its length from an older transfer's counter and rewrote memory past the buffer: panic, reset | **fixed**: length clamped, a cancelled read's memory untouched |
| H4 | Medium | MM and FS run privileged and the root file system is on the SD card: whoever writes the card owns the device | open, design (signed update S, later) |
| H5 | Medium | `FGIOCSET` let any process of group `gui` name any process as the foreground app, which a long Back then kills | **fixed**: others than root name only themselves, nobody, or a process of their own uid; M2 test |
| H6 | Low | Kernel task stacks have little slack against the static depth estimate (flipdev, SYS on the panic path) | open: measure on the device |
| H7 | Low | iButton emulation: an edge storm on the contact keeps the CPU in the interrupt handler | open |
| H8 | Low | `adc_put` kept up to 10 digits in a 6-byte array (the compiler's padding hid it) | **fixed**: 10 bytes, same stack frame |
| H9 | Info | Every process can read the whole flash (MPU region 0) | by design (XIP); no secrets in flash |

From earlier reviews: K4 (root on the console without a password) is still
deferred, temporarily, by the user's decision; K5 and K8 are open.

## H1: `DIOCSETP` on `/dev/rom`

`m_ioctl` passes `DIOCSETP` to `do_diocntl`, which stores the caller's base
and size without a check; `/dev/rom` is readable by everybody, and
`m_schedule` copies from `base + position`. A process that set base
`0x20000000` read the kernel, MM, FS and every other process; an unmapped
base gave a bus fault in the kernel, so a reset. Writes were refused
(`EROFS`). The kernel does not know uids, so FS refuses `DIOCSETP` from
anybody but the superuser, for every device ('d' is the disk ioctl group).
`repartition` runs as root and is unchanged.

## H2: `exec` and DMA

`flipdev_xit` stops what a process owns when it exits (#214). `exec` frees
the old image too (`sys_fresh`, `rmshadow`), but the descriptor stays open,
so nothing stopped the stream. `do_fresh` now calls `flipdev_xit` first.
In QEMU the old code kept playing an iButton pulse list out of freed memory
(the new M2 check, and two `ikey` checks after it, fail without the fix).

## H3: cancelled held RFID read

`ir_rx_end` took `ir_count / 4 - hal_pulse_left()` as the number of samples.
Before the capture is armed (the 450 ms settle time after a T5577 command)
the DMA counter is an older transfer's and may be larger: the unsigned
result wrapped, and `rf_durations` walked memory with it, also for a
cancelled read whose buffer nobody will look at. Now the count is clamped
to the buffer and durations are made only for a read that ended well.

## H5: `FGIOCSET`

The launcher (root) names its child as the foreground app. While nobody
was in the foreground, any process that could open `/dev/lcd` could name
any process above init: the user's long Back then sent it `SIGTERM` and
`SIGKILL`. FS now lets a caller that is not root name only itself, nobody
(0), or a process with its own real uid (an app's child, as `selftest`
does). `FGIOCPREEMPT` (alerts) is unchanged: it kills nothing and ends
with its caller.

## Not changed

H4, H6, H7 and H9 need a design decision or a measurement on the device
and are left for their own tasks.
